# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Purpose

A personal lab of independent AWS / DevOps sandboxes. Each top-level directory is a self-contained project — there is no shared build, no monorepo tooling, and no cross-project dependencies. Treat each subdirectory as its own root.

## Prerequisites

| Tool | Version |
|---|---|
| Terraform | >= 1.14.3 |
| AWS Provider | 6.31.0 |
| Node.js (Lambda runtime) | 24.x |
| AWS SAM CLI | >= 1.98 |
| Docker | any recent |
| Minikube | for local K8s |

## AWS Configuration

All AWS work uses region `us-east-1` and the named profile `malek`. Verify before running Terraform or SAM:

```bash
export AWS_PROFILE=malek
aws sts get-caller-identity
```

## Project Map & Commands

### `terraform-vpc-project/` — VPC + EC2 + Nginx
```bash
cd terraform-vpc-project
terraform init && terraform apply
terraform destroy
```
Splits resources across files by concern: `vpc.tf`, `subnet.tf`, `ec2.tf`, `data.tf`, `locals.tf`, `outputs.tf`, `variables.tf`. SG opens 22 and 8080 to `0.0.0.0/0` — fine for lab use, do not promote as-is.

### `terraform-lambda-project/terraform-example/infra/` — Lambda via Terraform
```bash
cd terraform-lambda-project/terraform-example/infra
terraform init && terraform apply
curl "$(terraform output -raw base_url)/hello"
terraform destroy
```
Terraform manages: Lambda (source in sibling `hello/`), API Gateway (`gateway.tf`), S3 deployment bucket (`lambda-bucket.tf`). Providers pinned to `aws=6.31.0`, `archive=2.3.0`, `random=3.7.2`.

### `terraform-lambda-project/myTestFunction-stack/` — Same Lambda via AWS SAM
```bash
cd terraform-lambda-project/myTestFunction-stack
sam build
sam local invoke LambdaFunctionFunctionmyTestFunction --event event.json
sam deploy --guided   # or: ../deploy.sh
```
Generated by the AWS Toolkit; coexists with the Terraform version as a deliberate side-by-side comparison of the two deployment styles for the same function.

### `Jenkins-Project/install.sh` — Jenkins in Docker
Not a script to execute — it's a reference of two `docker run` invocations (plain LTS, and DooD with the host docker socket mounted). Copy/paste the variant you need.

### `kuberentes-config.sh` — Minikube bootstrap
Filename is misspelled (`kuberentes`, not `kubernetes`) — use the actual filename. Deletes any existing cluster and starts a fresh one with 6 CPUs / 8 GB RAM.

### `terraform-eks-project/`, `vault-project/`
Empty placeholders. Do not assume contents.

## Gotchas

- **tfstate is committed** under `terraform-lambda-project/terraform-example/infra/`. Edits to infra mutate tracked files; do not lose state by force-cleaning the worktree. For team use, migrate to S3 + DynamoDB lock.
- **Real AWS costs**: every `terraform apply` and `sam deploy` provisions real resources. Always tear down (`terraform destroy` / `sam delete`) after experiments.
- **SAM resource name** is the verbose `LambdaFunctionFunctionmyTestFunction` (autogenerated by the toolkit) — keep it exact when invoking locally.
- **No tests, no linter, no CI** in this repo. "Build" means `terraform plan` / `sam build`; "run" means `apply` / `deploy` / `sam local invoke`.
